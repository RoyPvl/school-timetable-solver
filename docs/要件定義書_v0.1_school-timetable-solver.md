## 1. 文書の目的

本書は、塾の季節講座を対象とした「時間割解決システム」の業務要件、機能要件、非機能要件、制約および受入条件を定義するものです。

本システムは、教師、クラス、教室、校舎、開講日、必要授業数および各種運用ルールを入力として、条件を満たす時間割案を自動生成します。

## 2. 背景と課題

現在の時間割作成では、以下の条件を人手で同時に考慮する必要があります。

- 同一教師、同一クラス、同一教室の重複防止
- クラスおよび教科ごとの必要授業数
- 小学部、中学部、受験学年等による配置可能時限
- 休館日、お盆休み、短縮開講日等の年度固有日程
- 教師の休み日時
- 教師の期間別終日休日日数
- 教師の連続授業、公休、校舎移動
- クラスの1日最大コマ数、任意の連続登校Hard上限、推奨連続登校日数
- 校舎やクラスごとの個別例外

これらを人手だけで調整すると、作業時間が長くなり、条件漏れや重複が発生しやすくなります。また、年度ごとの日程変更や運用ルール変更に対して、再利用性が低いという問題があります。

## 3. システムの目的

本システムの目的は以下です。

1. 絶対に守るべき条件を満たす時間割案を自動生成する。
2. 教師およびクラスの負担を可能な限り平準化する。
3. 年度ごとに変わる日程や運用ルールをExcelで変更可能にする。
4. ルール変更時にプログラム修正を最小化する。
5. 解が存在しない場合に、不足条件や競合原因を利用者へ提示する。
6. 非IT利用者がExcelと実行ファイルだけで操作できるようにする。

探索性能の改善では、日単位の必要容量と時限配置を分解してよい。ただし、入力規約、
出力規約、Hard/Softルールの業務上の意味を変更してはならず、時間切れを解なしとして
報告してはならない。

## 7. 業務フロー

```text
1. 年度・講座情報を入力する
2. 開館日、休館日、利用可能時限を入力する
3. 校舎、教室、教師、クラスを更新する
4. 必要授業数と担当教師を入力する
5. 教師の休み日時だけを入力する
6. 固定授業および例外ルールを入力する
7. 入力検証を実行する
8. 診断生成を実行する
9. 未配置・競合を修正する
10. 厳密生成を実行する
11. 出力Excelを確認する
12. 必要に応じて条件を変更して再生成する
```

## 8. 基本方針

### 8.1 Excel主導の設定管理

年度、受験学年、月、校舎、クラス名などをPythonコードへ直接埋め込みません。

以下の情報はExcelで管理可能とします。

- 休館日
- お盆休み
- 特別開館日
- 短縮開講日
- 日付ごとの利用可能時限
- 受験学年区分
- クラス属性
- 日付範囲による条件変更
- 校舎別最大コマ数
- クラス別最大コマ数
- 学部・学年別配置可能時限
- 教師別最大コマ数
- 教師別最大連続コマ数
- 校舎移動に必要な空き時限数
- 選好制約の有効・無効および重み

### 8.2 属性ベースのルール管理

「受験学年なら」「8月以降なら」といった個別条件は、コードに固定しません。

クラスには属性を付与し、条件表がその属性を参照する方式とします。

例：

```text
division = elementary
grade = 6
exam_category = exam
campus_id = BAIKOEN
```

ルール例：

```text
対象属性: exam_category = exam
適用開始日: 2026-08-06
適用終了日: 2026-08-06
許可時限: 1,2,3
```

これにより、翌年度に受験学年や適用日が変わってもExcel変更のみで対応可能とします。

### 8.3 絶対制約と選好制約の分離

| 種別 | 意味 |
|---|---|
| 絶対制約 | 違反する時間割は出力しない |
| 選好制約 | 違反は許容するが、違反数や負担を最小化する |

## 9. 機能要件

### FR-01 基本設定管理

システムは、以下の基本設定をExcelから読み込めること。

- 年度
- 講座名
- 講座開始日
- 講座終了日
- 生成モード
- 探索時間上限
- 乱数シード
- 出力ファイル名

### FR-02 開講日管理

システムは、日付ごとに以下を設定できること。

- 開館・休館
- 利用可能時限
- 特別開館
- 短縮開講
- 備考

日曜日、お盆等をコードで判定せず、日付ごとの開講カレンダーを最終的な正とします。

### FR-03 校舎・教室管理

システムは、以下を管理できること。

- 校舎ID
- 校舎名
- 教室ID
- 教室名
- 教室の利用可能日・時限
- 校舎別の標準最大コマ数
- 校舎別の例外ルール

### FR-04 教師管理

システムは、教師ごとに以下を管理できること。

- 教師ID
- 氏名
- 担当可能教科
- 所属校舎
- 1日最大コマ数
- 最大連続コマ数
- 校舎移動可否
- 休み日時
- 希望日時
- 公休目標
- 固定日時休みまたは期間別の終日休日日数

### FR-05 クラス管理

システムは、クラスごとに以下を管理できること。

- クラスID
- クラス名
- 校舎
- 学部
- 学年
- 受験区分
- 任意の分類タグ
- 1日絶対上限
- 1日推奨上限
- 最大連続登校日数（任意）
- 推奨連続登校日数（任意）
- 配置可能時限の標準値

受験学年か否かは、クラス名から推測せず、Excelの属性値を使用します。

### FR-06 授業要求管理

システムは、以下を授業要求として管理できること。

- クラス
- 教科
- 必要コマ数
- 主担当教師
- 代替担当教師
- 教室候補
- 同一日に配置可能な最大コマ数
- 連続配置可否
- 固定担当か否か

### FR-07 固定授業管理

システムは、事前に確定している授業を固定配置として読み込めること。

固定授業が他の固定授業や教師休みと競合する場合は、生成前にエラーとします。

### FR-08 汎用ルール管理

システムは、Excelのルール表から次の条件を読み込めること。

- 適用対象種別
- 対象属性
- 適用開始日
- 適用終了日
- 曜日
- 校舎
- 許可時限
- 禁止時限
- 1日最大コマ数
- 最大連続コマ数
- 最大連続登校日数（任意）
- 推奨連続登校日数（任意）
- 優先順位
- 絶対制約・選好制約の区分
- ペナルティ重み

加えて、クラス・教科と日付・時限範囲を指定し、その範囲内の授業を厳密に`x`コマとする配置数ルールを管理できること。校舎はクラスから導出し、入力を重複させない。同一ルールの複数範囲は和集合、異なるルールは範囲が重複してもAND条件として扱う。`x=0`は対象範囲への配置禁止を表す。

### FR-09 入力検証

生成前に以下を検証すること。

- 必須項目の空欄
- ID重複
- 未登録教師、クラス、校舎、教室、教科の参照
- 数値項目の不正
- 開講期間外の日付
- 休館日の固定授業
- 教師休み日時の固定授業
- 同時刻の固定授業重複
- 必要授業数に対する候補枠不足
- 教師供給枠不足
- クラス供給枠不足
- ルールの優先順位競合
- 同一優先順位における矛盾した許可・禁止条件
- 配置数ルールの指定数が授業要求の必要コマ数を超えること
- 配置数ルールの範囲内・範囲外の候補枠不足

### FR-10 候補スロット生成

各授業要求について、以下を満たす候補だけを生成すること。

- 開館日
- 許可時限
- クラス条件
- 教師休み条件
- 教室条件
- 校舎条件
- 固定授業との非競合
- 適用ルールとの整合
- 配置数が0と指定された範囲の除外

### FR-11 時間割生成

システムは、OR-Tools CP-SATを使用して時間割を生成すること。

最低限、以下の絶対制約を満たすこと。

- 教師重複禁止
- クラス重複禁止
- 教室重複禁止
- 必要コマ数
- 休館日配置禁止
- 教師休み日時配置禁止
- 教師ごとの指定日集合内の終日休日日数
- 教師休み注記の校舎別出力容量
- 日別最大コマ数
- 連続コマ数
- 指定範囲内の厳密配置コマ数
- 連続登校日数
- 校舎移動条件
- 固定授業

### FR-12 診断生成

解が存在しない可能性がある場合に、未配置授業を許容して原因を診断できること。

診断結果には以下を含めます。

- 未配置授業
- 不足コマ数
- 候補日数
- 候補時限数
- 担当可能教師数
- 主な阻害条件
- 修正候補

### FR-13 選好最適化

以下を可能な限り満たすこと。

- 6限担当後の翌日1限回避
- 教師の空きコマ削減
- 教師の担当数平準化
- クラスの授業日分散
- クラスの日別授業が1コマだけになる配置の抑制
- 同一教科の過度な連続回避
- 推奨上限超過の回避
- 公休日数確保
- 校舎移動回数削減
- 希望日時の優先

### FR-14 結果検証

生成結果に対して、ソルバーとは別の検証処理を実行すること。

検証結果は以下を明示します。

- 教師重複件数
- クラス重複件数
- 教室重複件数
- 必要コマ不足件数
- 絶対制約違反件数
- 選好制約未達件数
- 教師別総コマ数
- クラス別総コマ数

### FR-15 Excel出力

以下をExcelへ出力すること。

- 全体時間割
- 教師別時間割
- クラス別時間割
- 教師別集計
- クラス・教科別集計
- 未配置授業
- 制約違反・注意事項
- 実行条件

### FR-16 実行ログ

## 10. 初期制約要件

### 10.1 絶対制約

| ID | 制約 |
|---|---|
| H01 | 同一教師の同時刻重複を禁止する |
| H02 | 同一クラスの同時刻重複を禁止する |
| H03 | 同一教室の同時刻重複を禁止する |
| H04 | 休館日には配置しない |
| H05 | 教師休み日時には配置しない |
| H06 | 各授業要求の必要コマ数を満たす |
| H07 | クラスの1日最大コマ数を超えない |
| H08 | 教師の1日最大コマ数を超えない |
| H09 | 教師の上限コマ数勤務は連続した時限ブロックに限定し、上限超過を禁止する |
| H10 | 最大連続登校日数が指定されたクラスはその日数を超えない |
| H11 | 同一教師の同日校舎移動を1回まで許可し、移動前後に1コマ以上の空きを必須とする |
| H12 | 固定授業を指定位置へ配置する |
| H13 | 日付・属性別の許可時限ルールを守る |
| H14 | 利用不可教室へ配置しない |
| H15 | 同一クラス・同一日の全授業を同一教室へ配置する |
| H16 | 同一クラスの授業間に連続2コマ以上の空きを作らない |
| H17 | クラス・教科ごとに指定した日時範囲内の授業数を厳密値と一致させる |
| H21 | クラス・日付ごとに指定した各必須時限へ授業を1件配置する |
| H18 | 教師ごとに指定した対象日集合内の終日休みを厳密日数確保する |
| H19 | 固定休みと選択休みの注記セル数を校舎の教室列数以内にする |
| H20 | 特別講座・まな・高校を除く、入力期間内の通常授業の実際の初回・最終日に担任が担当する通常授業を配置する |

### 10.2 選好制約

| ID | 制約 |
|---|---|
| S01 | 6限担当後の翌日1限を避ける |
| S02 | クラスの推奨上限超過を避ける |
| S03 | 教師の空きコマを減らす |
| S04 | 教師の担当コマ数を平準化する |
| S05 | クラスの授業日を分散する |
| S06 | 同一教科の連続配置を避ける |
| S07 | 教師の希望日時を優先する |
| S08 | 教師の公休日を確保する |
| S09 | 校舎移動回数を減らす |
| S10 | 同一教室を空き時限なしで別クラスへ交替する回数を減らす |
| S11 | 同一クラスの同日授業を連続した時限へ寄せる |
| S12 | 同一クラスの授業が1コマだけになる日を減らす |
| S13 | 同一クラスが連続時限で同じ教科を受ける回数を減らす |
| S14 | 同一クラス・同一教科が同日に複数配置される度合いを最優先で減らす |
| S15 | 同一クラス・同一教科が同日2コマ以上となった翌暦日の再配置を減らす |
| S16 | クラス・教科ごとの授業を、配置可能量に応じて日程全体へ比例配分する |
| S17 | クラス・教科ごとに、指定日時範囲内の授業数を入力した希望値へ近づける |
| S18 | クラスの推奨連続登校日数を超える連続窓を、長い連続ほど重くなるように減らす |
| S19 | 各授業を同一校舎内のより高いpriorityの教室へ配置し、低priority教室の使用を減らす |
| S20 | H20の初回日の最初コマと最終日の最後コマを担任の通常授業に寄せる |
| S21 | 対象日集合別の教師休日日数を入力した希望値へ寄せる |

`S16`は必要コマ数の多少にかかわらず全授業要求へ適用し、候補枠が存在しない日や候補時限の少ない日を同じ重みで扱わない。候補日ごとの配置可能コマ数を累積し、その比率に応じた累積目標コマ数と実配置累積数の差を最小化する。

`S12`は`S16`より上位とし、日程全体の分散を改善するために、クラスの授業が1コマだけとなる日を増やさない。`S16`より下位の目的では、`S16`で達成した全体値と各クラス・教科単位の達成値も悪化させない。これにより、全体件数を保ったまま偏りを別のクラス・教科へ付け替えることを防ぐ。

`S17`は入力Excelでクラス・教科、日時範囲、希望コマ数を指定できる選好とする。対象範囲内の生成数と希望値の絶対差を最小化し、実現できない場合も生成を失敗させない。優先度は既存の日時選好より低く、S13より後、日時配置を固定してS10を解く前に適用する。

`S18`は入力Excelでクラス属性・日付ごとの推奨連続登校日数を指定できる選好とする。推奨値を`P`、実際の暦日連続登校を`L`としたとき、`L <= P`は無罰、超過時は`1 + 2 + ... + (L - P)`の累積ペナルティとする。受験学年は全てSoft Constraintとして`P=3`、非受験学年は`P=2`かつH10の上限3とし、4日以上の連続登校を禁止する。S18はS11より後、S12より前に適用する。

`S19`は`05_教室.priority`を使用し、各授業について校舎内最高priorityとの差をペナルティとする。同値の教室は横並びとし、Hard Constraintにより必要な場合は低priority教室も使用できる。日時配置を固定した後、S10より先に最適化する。

## 11. ルールの優先順位

複数ルールが同時に該当する場合、以下の順序で解決します。

```text
1. 固定授業
2. 日付単位の明示ルール
3. クラス単位の明示ルール
4. 校舎単位のルール
5. 学部・学年・受験区分等の属性ルール
6. 全体標準ルール
```

同一階層では、Excel上の`priority`が大きいルールを優先します。

同一優先順位で相反する絶対制約が存在する場合は、自動解決せず入力エラーとします。

## 12. 生成モード

| モード | 内容 |
|---|---|
| 入力検証 | 入力矛盾のみを確認し、時間割は生成しない |
| 診断生成 | 未配置を許容し、不足原因を出力する |
| 厳密生成 | 必要コマ数と絶対制約を完全に満たす |
| 再現生成 | 指定シードを使用して同一条件で再実行する |

## 13. 非機能要件

### NFR-01 操作性

- 利用者は原則として1つのExcelだけを編集する。
- 編集可能セルを明示する。
- 入力候補はプルダウン等で制限する。
- Python、Git、コマンド操作を利用者へ要求しない。
- Windows上で実行ファイルをダブルクリックして利用できる。

### NFR-02 再現性

- 入力ファイル、設定、バージョン、乱数シードを記録する。
- 同一入力および同一シードで再現可能な結果を生成する。

### NFR-03 保守性

- 年度固有情報をコードへ埋め込まない。
- ルール追加は原則としてExcel変更で対応する。
- ソースコードを責務別に分割する。
- 制約ごとに自動テストを用意する。

### NFR-04 性能

初期目標は以下とします。

- 入力検証: 30秒以内
- 診断生成: 5分以内
- 厳密生成: 標準設定で10分以内
- 探索時間上限はExcelで設定可能

最適解の証明よりも、業務上使用可能な良好解を制限時間内に得ることを優先します。

### NFR-05 信頼性

- 結果出力前に独立した再検証を実施する。
- 絶対制約違反が1件でもある結果は正式出力扱いにしない。
- 入力ファイルを直接上書きしない。
- 出力ファイル名へ実行日時または版を付与する。

### NFR-06 監査性

- 使用した入力ファイルのハッシュ値を記録する。
- システムバージョンをログへ記録する。
- 適用されたルール一覧を出力する。
- 選好制約の違反内容とスコアを出力する。

### NFR-07 配布性

- Windows実行ファイルとして配布できること。
- 原則として追加のPython環境構築を不要とすること。

## 14. 前提条件

- 教師、クラス、校舎、教室には一意のIDを付与する。
- 必要授業数は利用者が確定して入力する。
- 教師休み日時だけを生成前に入力し、休み行がない日時は勤務可能とする。
- 日時固定の休みは教師休み表、日時を選択する終日休みは対象日集合別日数ルールに入力する。同一教師へ両方式を併用しない。
- Excel入力値を業務上の正とする。
- 既存出力Excelはレイアウトテンプレートとして利用し、入力マスタとしては利用しない。
- ルール表だけでは表現困難な特殊条件は、固定授業または将来の拡張制約として扱う。

## 15. 受入条件

初期リリースは以下を満たした場合に受入可能とします。

1. 教師重複が0件である。
2. クラス重複が0件である。
3. 教室重複が0件である。
4. 同一クラス・同一日の教室移動が0件である。
5. 同一クラスの授業間に連続2コマ以上の空きが0件である。
6. 絶対制約違反が0件である。
7. 厳密生成では必要授業数の不足が0件である。
8. 教室を空き時限なしで別クラスへ交替する配置が最小化対象になっている。
9. 同一クラスの最初と最後の授業の間に空き時限がある日が最小化対象になっている。
10. 同一クラスの授業が1コマだけになる日が低い優先度で最小化対象になっている。
11. 同一クラスが連続時限で同じ教科を受ける隣接ペアが低い優先度で最小化対象になっている。
12. 診断生成では未配置理由を一覧確認できる。
13. 年度ごとの休館日をExcelだけで変更できる。
14. 受験区分および適用期間による時限条件をExcelだけで変更できる。
15. 校舎別最大コマ数をExcelだけで変更できる。
16. 全体、教師別、クラス別時間割をExcelへ出力できる。
17. 非IT利用者が実行ファイルから生成できる。
18. 同一入力・同一シードの結果を再現できる。
19. クラス・教科と複数の日時範囲で指定した厳密配置数をExcelだけで変更でき、`0`件ルールを配置禁止として扱える。

## 16. 今後の要確認事項

以下は詳細設計前に実データで検証します。

- 合同授業のクラス・教師・教室表現
- 複数教師が同時に担当する授業
- 1授業が複数時限連続するケース
- 教師の校舎移動時間の実態
- 公休の厳密な算定方法
- 教室定員の必要性
- 出力Excelに必要な印刷設定
- 既存帳票におけるセル結合、色、罫線、数式の保持範囲

## 17. 改版方針

仕様変更は、以下のいずれかとして管理します。

- Excel設定値の変更
- Excelルール行の追加・変更
- マイナーバージョンアップ
- 制約エンジン拡張を伴うメジャー変更

コードを変更せずExcelだけで対応できる変更を優先します。
