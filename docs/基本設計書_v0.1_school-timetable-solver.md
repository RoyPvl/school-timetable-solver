## 1. 設計目的

本書は、時間割解決システムのアーキテクチャ、モジュール、データ構造、Excel入出力、ルール評価、時間割生成、検証、ログおよび配布方式の基本設計を定義します。

## 2. 設計方針

### 2.1 中核方針

```text
Excelで業務条件を管理
        ↓
Pythonで入力検証・正規化
        ↓
OR-Tools CP-SATで制約充足・最適化
        ↓
Pythonで独立再検証
        ↓
Excel帳票と診断結果を出力
```

### 2.2 技術選定

| 領域 | 採用技術 |
|---|---|
| 実装言語 | Python 3.12以降 |
| 最適化 | Google OR-Tools CP-SAT |
| Excel入出力 | PythonのExcel操作ライブラリ |
| 設定補助 | YAML |
| テスト | pytest |
| パッケージ管理 | uv |
| 型検査 | pyright |
| 静的解析・整形 | Ruff |
| 実行ファイル化 | PyInstaller |
| バージョン管理 | Git |
| CI | GitHub Actionsまたは同等環境 |

### 2.3 設計原則

- 年度固有値をコードへ埋め込まない。
- クラス名、教師名、校舎名による条件分岐を行わない。
- IDを内部参照の基準とする。
- Excel上の表示名と内部IDを分離する。
- 絶対制約と選好制約を分離する。
- ルールは優先順位付きで評価する。
- ソルバー出力を信用せず、独立検証する。
- 入力不備と解なしを区別する。
- 利用者向けExcelと計算用内部データ構造を分離する。

### 6.7 10_教師休み

利用者は、休みがある教師・日付だけを入力します。休み行がない日時は勤務可能です。

Excel形式：

| teacher_id | date | unavailable_periods | note |
|---|---|---|---|
| T001 | 2026-07-20 | ALL | 終日休み |
| T002 | 2026-07-20 | P1\|P2 | 午前休み |

`ALL`は全時限へ展開し、個別の時限休みは`P1|P2`のように半角パイプで指定します。
内部処理では、教師・日付・休み時限IDの集合へ正規化します。

日時をSolverに選択させる教師は`15_教師休日日数ルール`へ、教師ID、開始日、終了日、期間別の完全一致日数または最小・最大日数を入力します。複数期間の合計を固定する場合はグループIDとグループ合計日数も入力します。範囲内で希望する日数は`preferred_days_off`へ入力し、S21で優先します。同一教師を固定休みと期間別休日日数の両方へ登録しません。

## 8. ルール評価設計

### 8.1 評価順序

各対象・日付について、以下の順序で有効設定を決定します。

```text
1. 全体標準値を取得
2. 校舎標準値を適用
3. 属性ルールを適用
4. クラス・教師個別値を適用
5. 日付範囲ルールを適用
6. 固定授業を適用
7. 同一優先順位の矛盾を検証
```

### 8.2 優先順位

数値が大きいほど優先します。

推奨範囲：

| 優先度 | 用途 |
|---:|---|
| 0〜99 | 全体標準 |
| 100〜199 | 校舎・属性ルール |
| 200〜299 | 期間限定ルール |
| 300〜399 | 日付限定ルール |
| 400以上 | 個別例外 |

### 8.3 許可時限の解決

許可時限は、原則として高優先度ルールによる上書きとします。

ただし`hard`ルールが複数該当する場合、許可時限の積集合を使用します。

例：

```text
ルールA: 1,2,3,4
ルールB: 2,3
結果: 2,3
```

積集合が空になる場合は入力エラーとします。

### 8.4 最大コマ数の解決

- `override`は高優先度値で上書きします。
- 複数の`hard`上限が該当する場合は最小値を採用します。
- クラス個別値は、同優先度の校舎標準値より優先します。

## 10. 候補生成設計

授業要求ごとに、以下の組合せから日時候補を作成します。

```text
日付 × 時限 × 固定担当教師
```

以下を満たさない候補は変数作成前に除外します。

- 開館日である
- 時限が日付上利用可能である
- クラスの有効許可時限に含まれる
- 教師休みに指定されていない
- 校舎条件を満たす

現入力契約では、同一校舎内の教室に定員・用途・日時別可用性の差はなく、Softな`priority`だけが異なります。したがって教室IDをCandidateへ含めず、クラス・日付ごとの匿名教室番号を補助変数として作ります。探索後、匿名教室番号を教室の`output_order`へ対応させます。

これにより、教室をCandidateへ含める場合より対称性を抑えつつ、同一クラス・同一日の教室を固定できます。

## 11. ソルバー設計

### 11.1 配置変数

候補ごとにBoolean変数を作成します。

```text
x[requirement, date, period, teacher, campus] ∈ {0,1}
```

### 11.2 主な絶対制約

#### 必要授業数

```text
各授業要求の配置数 = required_periods
```

診断生成時は未配置変数を追加します。

#### 指定範囲内の厳密配置数

```text
同一授業配置数ルールの各セグメント
  → 日付・時限枠の和集合へ正規化

対象範囲内の配置数 = exact_periods
```

異なるルールは対象範囲が重複しても、それぞれをAND条件として適用します。`exact_periods=0`は単一候補で判定できるためCandidate生成時に`H17`として除外し、正の値はCP-SATの`LessonCountInScopeConstraint`で制約化します。校舎は入力させずクラスから導出します。

#### 指定範囲内の希望配置数

```text
同一授業配置数選好ルールの各セグメント
  → 日付・時限枠の和集合へ正規化

S17 penalty = abs(対象範囲内の配置数 - preferred_periods)
```

`preferred_periods=0`でもCandidateを除外せず、Hard Constraintを満たす解の中で対象範囲への配置をなるべく避けます。異なるルールは範囲が重複してもそれぞれの偏差を独立に評価します。

#### 教師重複

```text
同一教師・同一日・同一時限の配置数 <= 1
```

#### クラス重複

```text
同一クラス・同一日・同一時限の配置数 <= 1
```

#### 教室容量

```text
同一校舎・同一日・同一時限の配置数
<= 当該校舎の有効教室数
```

探索成功後に重複しない実教室を割り当て、独立結果検証では実教室IDを使って教室重複0件を確認します。

#### クラス教室継続

```text
同一クラス・同一日の選択済み授業
→ 同じ匿名教室番号
```

同時刻に授業がある異なるクラスの匿名教室番号は異ならなければなりません。

#### クラス授業の連続性

同一クラス・同一日の各時限に授業有無のBool変数を作ります。授業に挟まれた連続2時限が両方とも空きになる配置は`H16`として禁止します。

空き1時限は許可し、最初と最後の授業の間に空き時限がある日をペナルティとして数えます。これは`S11`の選好制約であり、参照実績に例外があるため空き1時限は禁止しません。

授業が1コマだけになるクラス日をペナルティとして数えます。これは`S12`の低優先度の選好制約であり、必要コマ数や日程条件によって避けられない場合があるため禁止しません。

同一クラス・同一教科が連続時限へ配置された隣接ペアをペナルティとして数えます。これは`S13`の低優先度の選好制約であり、2連続は1、3連続は2のように長い連続ほどペナルティが増えます。参照実績にも2連続の例外があるため禁止しません。

同一クラス・同一教科・同一日の授業数を`n`とし、授業ペア数`n × (n - 1) / 2`を`S14`のペナルティとして数えます。現入力のように日別上限が2の場合は、同日2コマの日数と一致します。3コマ以上を許す入力でも、1、3、6と増えるため一日に集中させず分散を優先します。

同一クラス・同一教科が同日2コマ以上となり、その翌暦日にも1コマ以上ある組み合わせを`S15`のペナルティとして数えます。日付は出力順の隣接ではなく`対象日 + 1日`で比較し、休講日をまたぐ配置は対象外とします。

クラス・教科ごとの授業要求について、Candidateが存在する日を日付順に`d1...dm`、日別の配置可能コマ数を`c_i`、必要コマ数を`R`とします。`c_i`はCandidateの異なる時限数を、授業要求日別上限・クラス日別上限・`R`で制限した値です。累積容量`C_i`に対する累積目標`T_i = round_half_up(R × C_i / C)`と、実配置累積数`A_i`の差を`S16`として最小化します。

```text
S16 score
= ceil(
    1000 × Σ |A_i - T_i|
    / (R × (m - 1))
  )
```

最終日は必要コマ数制約により累積差が必ず0になるため集計から除外します。`R <= 1`、候補日が1日以下、または総容量が必要数以下で配置自由度がない授業要求にはS16を作りません。正規化スコアを使うため、コマ数の少ない教科も多い教科に埋もれず、全授業要求へ同じ基準で適用できます。

#### 教室交替の空き時限

同一教室を連続時限で別クラスへ交替する組み合わせをペナルティとして数え、総数を最小化します。これは`S10`の選好制約であり、解を失わないよう配置自体は禁止しません。

#### 教室priority

各授業について、所属校舎内の最高`priority`と割当教室の`priority`との差を`S19`のペナルティとして数えます。数値が大きい教室ほど優先し、同値は横並びです。日時配置を固定した後、S10より先に最小化します。

#### 日別上限

```text
対象日のクラス配置数 <= EffectiveClassPolicy.daily_hard_limit
```

#### 連続コマ上限

教師の任意の連続窓について、上限を超える配置を禁止します。

#### 連続登校上限

クラスの任意の暦日連続窓について、`attendance_streak_limit`が指定された日を終端とする上限超過を禁止します。値が空欄の日はH10を適用しません。

#### 担任授業期間の初回・最終日

H20の対象日`d`について、通常授業有無を`A[d]`、担任通常授業の配置数を`E[d]`とします。初回・最終日の条件は次の等価な線形式で表現し、Hard探索では境界日のone-hot変数を作りません。

```text
A[d] <= E[d] + sum(A[dより前])
A[d] <= E[d] + sum(A[dより後])
```

最初の通常授業日は前方の合計が0、最後の通常授業日は後方の合計が0になるため、それぞれ当日の担任通常授業が必須になります。S20の最初・最後のコマ判定に必要な境界日変数は、Softフェーズで遅延生成します。

#### 推奨連続登校日数

クラスの暦日連続登校列について、日ごとにその日を終端とする`preferred_attendance_streak_limit`超過窓をS18として数えます。推奨値`P`が一定の場合、連続長`L <= P`は0、`L > P`は次式です。

```text
S18 penalty = 1 + 2 + ... + (L - P)
```

したがって`P=3`では3日、4日、5日、6日連続のペナルティはそれぞれ0、1、3、6です。開講カレンダーに暦日の欠落があれば連続列を分断します。

#### 校舎移動

異なる校舎間では、教師の`required_transfer_gap`以上の空き時限を要求します。

#### 教師の期間別終日休み

教師・日付ごとに終日休みBool変数を作り、各入力期間の合計を`required_days_off`と一致させるか、`minimum_days_off`以上`maximum_days_off`以下にします。グループ指定がある場合は、対象期間を合算して`group_required_days_off`とも一致させます。終日休み変数が真の日は、その教師の授業配置数を0とします。固定休みと選択休みの注記セル数は、日付・所属校舎ごとに有効教室数以下とします。

### 11.3 選好制約

各選好違反にペナルティ変数を作成し、優先度が高い目的から段階的に最小化します。

```text
第1段階:
  S14 同一クラス・同一教科・同一日の授業ペア数を最小化

第2段階:
  S15 同日2コマ以上となった翌暦日の同一教科配置を最小化
  → S14の全体値と各クラス・教科別の達成値を悪化させない

第3段階:
  S11 同一クラスの同日授業間に空き時限がある日を最小化
  → S14・S15の達成値を悪化させない

第4段階:
  S18 クラスの推奨連続登校日数を超える連続窓を最小化
  → S14・S15・S11の達成値を悪化させない

第5段階:
  S12 同一クラスの授業が1コマだけになる日を最小化
  → S14・S15・S11・S18の達成値を悪化させない

第6段階:
  S16 候補日別容量に比例した累積目標との差を最小化
  → S14・S15・S11・S18・S12の達成値を悪化させない

第7段階:
  S13 同一クラスが連続時限で同じ教科を受ける隣接ペアを最小化
  → S14・S15・S11・S18・S12・S16の達成値を悪化させない

第8段階:
  S17 指定日時範囲内の授業数と希望値の絶対差を最小化
  → S14・S15・S11・S18・S12・S16・S13の達成値を悪化させず、達成した日時配置を固定

第9段階:
  S19 各授業の教室priorityと校舎内最高priorityとの差を最小化

第10段階:
  S10 匿名教室を連続時限で別クラスへ交替する回数を最小化
```

### 11.4 初期重み

| rule_id | 優先度 | ペナルティ単位 |
|---|---:|---|
| S20 | 35 | 境界日の最初・最後のコマが担任の通常授業でない1件 |
| S21 | 34 | 期間別休日数と`preferred_days_off`の差1日 |
| S14 | 30 | 同一クラス・同一教科・同一日の選択授業ペア1組 |
| S15 | 25 | 同日2コマ以上の翌暦日にも同じ教科がある組み合わせ1件 |
| S11 | 20 | 分割があるクラス日1件 |
| S18 | 18 | 推奨連続登校日数を超える暦日連続窓1件 |
| S12 | 15 | 授業が1コマだけのクラス日1件 |
| S16 | 14 | 候補容量比の累積目標との差を0〜1000へ正規化したクラス・教科別スコア |
| S13 | 12 | 連続時限で同じ教科を受ける隣接ペア1件 |
| S17 | 11 | 指定日時範囲内の生成数と希望値の絶対差1コマ |
| S19 | 10 | 1授業ごとの校舎内最高priorityとの差 |
| S10 | 9 | 空き時限なしの教室交替1件 |

本入力契約では重みをExcelから変更しません。S17はルールごとの希望値と対象範囲、S18はクラス・日付ごとの推奨連続登校日数だけをExcelから設定します。将来Soft Constraintを追加する場合は、同じ優先度で合算できるか、別段階にするかを業務上の優先順位から決定します。

## 22. 設計上の判断まとめ

1. 休館日とお盆休みは開講カレンダーで管理します。
2. 受験学年はクラス属性として管理します。
3. 「8月以降」は日付範囲ルールとして管理します。

7. ルール競合は自動的に曖昧解決せず、入力エラーとして明示します。
