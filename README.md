# school-timetable-solver

Excelで管理する開講日、時限、校舎、教室、教師、クラス、教科、授業要求、教師休み、配置ルールを読み込み、Google OR-Tools CP-SATでHard Constraintを満たす時間割を生成するローカルCLIです。

## PoCの対象範囲

- 入力契約v1.1の18シートExcel
- `validate_only`による形式・参照・ルール解決・明白な供給不足の検証
- `strict`による全必要授業数を満たす時間割生成
- 教師・クラス・教室重複、必要コマ数、範囲内厳密配置数、日別上限、連続時限、連続登校、同日単一校舎、同一クラス・同日単一教室、クラス授業間の連続2コマ以上の空き禁止のHard Constraint
- `17_クラス組重複禁止ルール`で指定したクラス組について、H22の同時刻重複禁止に加え、H23としてsecond classを同日のfirst class最終コマ直後・同一教室へ配置するHard Constraint
- 1日1コマ登校の回避、同日授業の連続化、同一教科の連続・同日複数配置の回避を最上位とし、その後に翌日再配置、連続登校、配置数選好、教師休み・校舎移動、教科分散、教室選好を段階最適化するSoft Constraint
- カレンダー、教師休み、クラス許可時限、無効校舎のCandidate事前除外
- 日時決定と教室割当の分離による、同等教室の対称性を除いた探索
- OR-Toolsとは独立した結果検証
- `全体`1シートの日付別時間割マトリクス出力
- 各日付の表直下への校舎別教師休み注記出力
- テキスト実行ログ

固定授業、代替担当教師、複数担当教師、条件付き校舎移動、S10・S11・S12・S13・S14・S15・S16・S17・S18・S19以外のSoft Constraint、`diagnostic`、Unsat Core、教師別・クラス別・集計・検証結果等の補助Worksheet、GUI、実行ファイル化、デプロイ、CIはPoC対象外です。

## 必要環境

- Python 3.12以降
- uv 0.11以降

## セットアップ

```bash

```

## サンプル実行

```bash
uv run python -m school_timetable_solver.main \
  --input projects/sample/input/時間割入力_サンプル.xlsx \
  --output projects/sample/output/時間割生成結果_サンプル.xlsx \
  --log projects/sample/output/時間割生成_サンプル.log \
  --mode strict \
  --max-solve-seconds 60 \
  --random-seed 1 \
  --num-search-workers 8
```

CLI引数:

| 引数 | 内容 | Default |
|---|---|---:|
| `--input` | 入力Excel | 必須 |
| `--output` | 出力Excel | 必須 |
| `--log` | 実行ログ | 任意 |
| `--mode` | `strict` / `validate_only` | `strict` |
| `--max-solve-seconds` | 正の実数 | `60.0` |
| `--random-seed` | 0以上の整数 | `1` |
| `--num-search-workers` | 1以上の並列探索数。再現性優先時は`1` | `8` |

`validate_only`ではSolverを実行せず、時間割Excelも生成しません。入力エラー、候補不足、解なし、結果検証エラー時にも出力Excelを生成・置換しません。

現入力契約では、同一校舎内の有効教室に定員・用途・日時別可用性の差はなく、Softな`priority`だけが異なります。そのためCandidateへ実教室IDは持たせず、CP-SAT内でクラス・日付ごとの匿名教室番号だけを決めます。H15により同じクラスの同日中の授業は同じ匿名教室とし、H03により同時刻の重複を禁止します。H16は同一クラスの授業間に連続2コマ以上の空きを禁止し、空き1コマは許可します。Soft Constraintはpriorityの大きい階層から辞書式に段階最適化し、上位階層で得たペナルティ値を悪化させない範囲で下位階層を改善します。同一priorityのルールは同一階層としてペナルティ合計を最小化します。日時配置ではS12、S11、S13/S14、S15、S18、S23、S17、S21/S22、S16、S20の順で重視し、その後に教室系のS19、S10を最適化します。S18はクラスの推奨連続登校日数以下を無罰とし、超過が続くほど累積的に重くします。S16は候補日別の配置可能コマ数に応じて各教科を日程全体へ比例分散します。S17は指定日時範囲内の授業数と希望値との差を減らします。S21はH18で許容された休日配分のうち期間別の希望日数へ寄せ、S22は同日校舎移動時にできれば2コマ以上の余裕を確保します。S19は低priority教室の使用を減らし、S20はH20で保証された初回・最終登校日の担任授業をその日の端のコマへ寄せます。S10は同じ教室を連続時限で別クラスへ交替する回数を減らします。ただしH23で必須となる登録済み`first_class_id -> second_class_id`の連続・同一教室遷移はS10の対象外です。S12はH23の`second_class_id`に加え、有効な授業要求の教科が1種類だけのクラスも対象外です。解の後で匿名教室番号を`output_order`順の実教室IDへ変換し、Hard ConstraintとSoft Constraintスコアを独立再検証します。

### Soft Constraint優先順位

| priority | Rule | 目的 |
|---:|---|---|
| 100 | S12 | 1日1コマだけの登校日を減らす（H23 second classと1教科クラスは対象外） |
| 90 | S11 | 同じクラスの1日の授業を連続ブロックへ寄せ、内部空きを減らす |
| 80 | S13 / S14 | 同一教科の連続時限と、同日複数コマ配置を減らす |
| 70 | S15 | 同日2コマ以上実施した教科の翌暦日再配置を減らす |
| 60 | S18 | 推奨連続登校日数を超える登校を累積的に減らす |
| 50 | S23 | 教師の最終時限担当→翌暦日最初時限担当を減らす |
| 40 | S17 | 指定日時範囲内の授業数を希望値へ寄せる |
| 30 | S21 / S22 | 教師の希望休日日数と、校舎移動時の余裕を改善する |
| 20 | S16 | 各クラス・教科を候補容量に応じて日程全体へ分散する |
| 10 | S19 / S20 | 高priority教室の使用と、担任授業の端コマ配置をなるべく実現する |
| 5 | S10 | 同一教室で連続時限に別クラスへ交替する回数を減らす |

## 入力・出力

入力Workbookは次の18シートです。

```text
00_操作説明
01_基本設定
02_開講カレンダー
03_時限
04_校舎
05_教室
06_教師
07_クラス
08_教科
09_授業要求
10_教師休み
11_配置ルール
12_選好設定
13_授業配置数ルール
14_授業配置数選好ルール
15_教師休日日数ルール
16_担任授業期間ルール
17_クラス組重複禁止ルール
```

`10_教師休み`には休みがある教師・日付だけを入力します。終日休みは
`unavailable_periods=ALL`、時限休みは`P1|P2`形式で指定し、行がない日時は勤務可能です。
`05_教室.priority`は0以上の整数で、大きいほど優先します。同じ値の教室は横並びです。
`06_教師.home_campus_id`は、教師休み注記を所属校舎の教室列へ配置するために使用します。
`06_教師.teacher_name`を空欄または空白だけにした場合は、空き教師を表す空文字列として読み込み、出力の担当欄を空セルにします。`teacher_id`は通常どおり一意な値が必要です。
`08_教科.subject_name`を空欄または空白だけにした場合も、空文字列として読み込み、出力の教科欄を空セルにします。`subject_id`は通常どおり一意な値が必要です。
`13_授業配置数ルール`では、校舎を入力せず`class_id`から導出します。同一`rule_id`の複数行は日時範囲の和集合、異なるルールは重複していてもAND条件です。`exact_periods=0`は対象範囲への配置禁止を表します。

`14_授業配置数選好ルール`は同じ設計で、`preferred_periods`と対象日時範囲を指定します。未達を許容するS17として扱い、`preferred_periods=0`でも候補は除外せず、Hard Constraintを守った上で対象範囲への配置をなるべく減らします。

`16_担任授業期間ルール`は、条件に合うクラスと期間を指定します。H20は、授業種別を問わず対象クラスの有効授業がある実際の初回・最終登校日に、担任の通常授業を必須とします。S20はその日の最初・最後のコマへ優先します。

`17_クラス組重複禁止ルール`は、別IDで管理する2クラスを`first_class_id`と`second_class_id`で指定します。H22として同日・同時限への同時配置を禁止し、さらにH23として、second classがある日は登録されたfirst classのいずれかが同日1コマ以上存在し、second classの最初のコマを選択されたfirst classの最終コマ直後かつ同一教室へ配置します。first classの当日授業自体は連続している必要はありません。1つのsecond classに複数のfirst classが登録されている場合はOR条件として扱い、いずれか1つのfirst classの直後であれば成立します。指定した組はH10/S18でも従来どおり1つの登校グループとして扱い、どちらかに授業がある日をその組の登校日とします。同じクラスを複数の組へ指定した場合は、組ごとに独立して連続登校を判定します。

`11_配置ルール`の`attendance_streak_limit`はH10の任意Hard上限、`preferred_attendance_streak_limit`はS18の推奨値です。テンプレートでは受験学年を推奨3・Hard上限なし、非受験学年を推奨2・Hard上限3としており、非受験学年の4日以上連続登校を禁止します。

出力Workbookは`全体`シート1枚だけを持ちます。出力対象日を日付昇順に1行2日ずつ配置し、各日を校舎・教室列、6時限×クラス・教科・担当行のマトリクスで表示します。表直下には、終日休みを教師名だけ、時限指定休みを教師名と丸付き時限で校舎別に左詰め表示します。

## 終了コード

| Code | Meaning |
|---:|---|
| 0 | 入力検証成功、またはstrict生成成功 |
| 1 | 予期しない内部エラー、Solverの予期しない状態 |
| 2 | 入力形式・入力整合性・ルール解決・候補不足エラー |
| 3 | strict生成で`INFEASIBLE`または`UNKNOWN` |
| 4 | 独立結果検証またはDocument構築エラー |
